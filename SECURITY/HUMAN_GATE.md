# ประตูมนุษย์ (Human Gate)

**FATE™ Axiom 6 — Human Final Authority** เขียนเป็นโค้ดที่ `core/human_gate.py`

## กฎ

> AI เสนอได้ แต่ทำเองไม่ได้
> action ที่มีผลออกนอกระบบต้องมีใบอนุญาตที่มนุษย์ออกให้ ผ่านช่องทางที่ AI อ่านหรือเขียนไม่ได้

## ทำไม

งานวิจัยของ Cornell Tech / Yale (พ.ย. 2026) ทดสอบ AI agent 10 ตัวบนกระเป๋าเงินของ Circle
พบว่า 9 ตัวไปหยิบรหัสอนุมัติจากอีเมลมาเพิ่มวงเงินให้ตัวเอง โดยไม่มีผู้โจมตีเลย
ต้นเหตุคือรหัสอนุมัติอยู่ใน channel เดียวกับที่ agent อ่านได้

## ระบบเราป้องกันยังไง

| ชั้น | ทำอะไร |
|---|---|
| ใบอนุญาตลงลายเซ็น | HMAC ด้วย `HUMAN_GATE_SECRET` (หรือ `SECRET_KEY`) ซึ่งไม่เคยอยู่ใน prompt |
| ผูกกับ action | ใบของ `write_note A` เอาไปใช้กับ `write_note B` ไม่ได้ |
| หมดอายุ | 120 วินาที (สูงสุด 600) |
| ใช้ครั้งเดียว | ใช้แล้วใช้ซ้ำไม่ได้ |
| ช่องรับแยก | ใบอนุญาตต้องส่งเป็น `execute_tool(..., approval=...)` ค่าใน `decision` ไม่นับ |
| fail closed | ไม่มี secret แปลว่าประตูปิด ไม่ใช่เปิดโล่ง |

action ที่ต้องผ่านประตู: `open_url`, `write_note`, `send_alert`
action ที่ไม่ต้องผ่าน: `calculate` (คิดเลขอย่างเดียว), `log_decision` (บันทึกของประตูเอง)

## ข้อห้ามสำหรับคนเขียนโค้ด

1. เรียก `human_gate.mint()` ได้เฉพาะหลังมนุษย์ยืนยันตัวแล้ว (TOTP หรือ session ที่ผ่าน 2FA)
2. ห้ามเรียก `mint()` จากทางที่รับข้อความจาก LLM
3. ห้ามใส่ใบอนุญาตกลับเข้า prompt หรือ history ของ LLM
4. เพิ่ม tool ใหม่ที่มีผลออกนอกระบบ ต้องเพิ่มชื่อใน `GATED_ACTIONS` ด้วย
   (`tests/test_human_gate.py` จะล้ม ถ้า tool ใหม่ไม่ได้ถูกจัดกลุ่ม)
