# ความพร้อมรับคอมพิวเตอร์ควอนตัม — สิ่งที่เป็นจริงของ KING DIADEM

เขียนให้ตรงกับของจริงในโค้ด ไม่อ้างเกิน ตรวจซ้ำได้ด้วย `tests/test_quantum_readiness.py`

## QKD ใช้กับเว็บนี้ไม่ได้ และทำไม

QKD (Quantum Key Distribution) ต้องส่งโฟตอนทีละตัวผ่านใยแก้วหรือดาวเทียมระหว่างเครื่องส่งกับเครื่องรับที่เป็นฮาร์ดแวร์ควอนตัมจริง
เบราว์เซอร์ มือถือ และเซิร์ฟเวอร์ของเราไม่มีอุปกรณ์นั้น ข้อมูลระหว่างผู้ใช้กับเว็บวิ่งผ่านอินเทอร์เน็ตปกติ
ดังนั้นโค้ด Python ที่รับค่า QBER แล้วคืนคำว่า "ปลอดภัย" **ไม่ได้ป้องกันอะไร** เพราะไม่มีช่องควอนตัมให้วัด
เราจึงไม่ใส่ฟังก์ชันแบบนั้นในระบบ และไม่เขียนในหน้าเว็บว่า "ป้องกันระดับควอนตัมด้วย QKD"

หลักคิด "การแอบดูต้องทิ้งร่องรอย" ยังใช้เป็นหลักออกแบบได้ และระบบมีของจริงที่ทำหน้าที่นั้นอยู่แล้ว:
บันทึกตรวจสอบแบบ hash-chain (`core/audit_log.py`) — แก้ย้อนหลังบรรทัดไหน โซ่จะขาดให้เห็น

## ภัยจากควอนตัมจริงๆ คืออะไร

| ส่วน | อัลกอริทึม | ควอนตัมทำอะไรได้ | สถานะ |
|---|---|---|---|
| รหัสผ่าน | PBKDF2-HMAC-SHA256 600,000 รอบ (`DATABASE/db.py`) | Grover เร็วขึ้นแค่รากที่สอง ไม่ทำให้แตก | ปลอดภัย |
| ลายเซ็นภายใน · 2FA · audit log | HMAC-SHA256 · TOTP · SHA-256 | เหมือนข้างบน | ปลอดภัย |
| โทเคนสุ่ม | `secrets` (สุ่มจากระบบปฏิบัติการ) | ตรวจได้ทางเซิร์ฟเวอร์เท่านั้น ควอนตัมไม่ช่วยผู้โจมตี | ปลอดภัย |
| การเชื่อมต่อ HTTPS | TLS 1.3 · แลกกุญแจด้วย X25519 (ตรวจเมื่อ 2026-11-12) | Shor ถอดการแลกกุญแจได้ — "ดักเก็บวันนี้ ถอดรหัสวันหน้า" | **จุดเดียวที่เสี่ยง** |

ในโค้ดของเราไม่มี RSA หรือ ECC เลย (ไม่มีไลบรารี `cryptography` / `rsa` / `ecdsa` / `jwt`) จุดที่ควอนตัมคุกคามจึงมีที่เดียวคือ TLS
ซึ่งผู้ให้บริการโฮสต์ (Render) เป็นคนตั้งค่า ไม่ใช่โค้ดใน repo นี้

## ทางแก้ที่ใช้ได้จริง: การเข้ารหัสหลังควอนตัม (PQC)

มาตรฐานที่ใช้กันแล้วคือการแลกกุญแจแบบผสม `X25519MLKEM768` (ML-KEM · NIST FIPS 203) ใน TLS 1.3 — Chrome, Firefox, Safari รุ่นใหม่รองรับแล้ว
ไม่ต้องใช้ฮาร์ดแวร์พิเศษ และป้องกัน "ดักเก็บวันนี้ ถอดรหัสวันหน้า" ได้

- ตรวจว่าเว็บเราใช้อยู่ไหม: เปิดเว็บใน Chrome → DevTools → แท็บ Security (หรือ Privacy and security) → ดูบรรทัด Key exchange
  ถ้าเห็น `X25519MLKEM768` แปลว่าใช้แล้ว · เครื่องทดสอบของเรา (OpenSSL 3.0) ยังตรวจกลุ่มนี้ไม่ได้ จึง**ยังไม่ได้ยืนยัน**
- ถ้ายังไม่ใช้: วาง Cloudflare (แผนฟรี) หน้าโดเมน — เปิด PQC hybrid ให้ผู้ใช้ทุกคนโดยไม่ต้องแก้โค้ด

## ข้อสังเกตจากการไล่ดูโค้ด

- `app.py` `_mkey`: HMAC ตัดเหลือ 20 ตัวอักษรฐานสิบหก (80 บิต) — ดูแล้วเป็น "รหัสแทนตัวผู้ใช้" สำหรับนับสถิติโดยไม่เก็บอีเมล ไม่ใช่ลายเซ็นยืนยันสิทธิ์
  จึงไม่ใช่ช่องโหว่ และ**ไม่ควรยืด** เพราะรหัสที่เก็บไว้แล้วจะไม่ตรงกับของใหม่
