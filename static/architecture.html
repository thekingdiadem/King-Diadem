Architecture · สถาปัตยกรรมระบบ

KING DIADEM ทำงานอย่างไร

ระบบนี้เป็น monolith แบบเป็นชั้น คือเซิร์ฟเวอร์ FastAPI ตัวเดียว ที่ให้ตรรกะของระบบล้อม AI ไว้ทั้งก่อนและหลัง AI เป็นแค่ “เสียง” ที่เรียบเรียงคำตอบ ไม่ใช่ผู้ตัดสิน และถ้า AI ไม่อยู่ ระบบยังตอบได้จากสมการของตัวเอง

01 · Pattern

เป็นสถาปัตยกรรมแบบไหน

Layered monolith

ทุกอย่างอยู่ในโปรแกรมเดียว

app.py รับทุกคำขอ แล้วเรียกชั้นตรรกะ (core/ ENGINE/ AI/ AI_KERNEL/) เป็นฟังก์ชันในตัว ไม่มี microservice รันบน Render ด้วย gunicorn 1 worker · เก็บข้อมูลใน SQLite บนดิสก์ถาวร — ไล่เหตุผลได้ทุกบรรทัด

Kernel sandwich

ตรรกะประกบ AI ไว้

ก่อนถึง AI: อ่านสัญญาณ ความเสี่ยง เส้นทาง และใส่ตัวเลขจริง · หลัง AI: ตัดทางเลือกให้ไม่เกิน 3 แล้วผ่านประตู Cosmic Latte Canon ถ้าคำตอบบีบจนเหลือทางเดียวหรือบังคับตัวตน จะถูกหยุดและใช้คำตอบจากสมการแทน

AI-optional

ไม่มี AI ก็ยังตอบได้

AI ล่ม โควตาหมด หรือไม่มี key → core/kernel_voice.py ตอบจากสมการ W · Risk · Choice(t) แบบเดิมทุกครั้ง (deterministic) AI ใช้ Gemini ผ่าน core/llm_gemini.py ที่หมุน key และสลับรุ่นสำรองได้เอง

Human final authority

มนุษย์เลือกเองเสมอ

ระบบไม่ตัดสินแทน — มีทางเลือก ≥ 1 ระบบเงียบ (Silent Canon) · เหลือ 0 ระบบคืนให้ 1 ทางแล้วถอย สิ่งที่เก็บเพื่อเรียนรู้เป็นแค่ตัวเลข (เส้นทาง · ความเสี่ยง · ผลโหวต) ไม่เก็บข้อความ

Human

คนพิมพ์ข้อความในหน้าเว็บ

Kernel · ก่อน

ตรวจโควตา · อ่านสัญญาณภาษาไทย/5 ภาษา · ความเสี่ยง · เส้นทาง · บริบทเหตุปัจจัย · ตัวเลขจริง (หนี้ เวลา ทรัพยากร)

AI · เสียง

Gemini เรียบเรียงคำตอบตามบุคลิก LYLA / VEGA / สภา — ถ้าไม่มี AI ข้ามชั้นนี้ไปใช้คำตอบจากสมการ

Kernel · หลัง

ทางเลือก ≤ 3 · ประตู Canon · Belief Core · บันทึกตัวเลข · สร้างรายงานแชร์ได้

Human

คนอ่าน แล้วเลือกเอง

02 · One message

ข้อความหนึ่งข้อความเดินทางอย่างไร

เส้นทางจริงของ POST /run ตามลำดับในโค้ด — แตะชื่อไฟล์เพื่อดูว่าไฟล์นั้นเชื่อมกับอะไรในแผนที่ด้านล่าง

  1. หน้าเว็บส่งข้อความbrowser

    แอปหน้าเดียวส่งข้อความพร้อมเส้นทางและบุคลิกที่เลือก แชทเก็บไว้ในเครื่อง และซิงก์ขึ้นเซิร์ฟเวอร์เมื่อเข้าสู่ระบบ

  2. ประตูหน้าgate

    ตรวจความยาวข้อความ อัตราการส่ง และโควตา (ฟรีวันละ 20 ข้อความ → เครดิต → Premium) ถ้านับโควตาไม่ได้ ยังตอบได้แต่ตอบจากสมการเท่านั้น

  3. อ่านสัญญาณsignals

    สถานะคน เจตนา ความเสี่ยงจากตัวเลขและจากข้อความ ภาษาที่ใช้ และสัญญาณเฉพาะ เช่น วิกฤต มิจฉาชีพ ถูกทำร้าย ภัยพิบัติ — ยกเส้นทางขึ้นได้อย่างเดียว ไม่ลด

  4. ใส่บริบทcontext

    ร้อยบริบทเหตุปัจจัย (ปฏิจจสมุปบาท) ความว่าง (Cosmic Latte) สัญญาณวิกฤตและสายด่วน (Living Water) นิทาน และทางออก แล้วต่อเครื่องยนต์ตัวเลขจริง เช่น แผนปลดหนี้ เวลาที่มี ทรัพยากรพอใช้กี่วัน กำไรและ margin ของร้าน

  5. ตรวจความเชื่อbelief audit

    Belief Core ตรวจว่าการอยู่รอดยังผ่านไหม ถ้าไม่ผ่านจะสั่ง SYSTEM_PAUSE แล้วคืนคำตอบที่ปลอดภัยทันที

  6. เครื่องยนต์ตัดสินใจdecision

    อ่านรูปแบบ → ตรวจสุญญตา (ถอดป้ายชื่อแล้วต้องยังมีทางเลือก ≥ 1) → ศูนย์กลางเครื่องยนต์: ปฏิจจสมุปบาท → ความเสี่ยง → สภา 6 เสียง → จำลอง → กลยุทธ์ → ทางรอด

  7. เสียง: AI หรือสมการvoice

    Gemini เรียบเรียงคำตอบด้วย system prompt ของ LYLA / VEGA / โหมดวิกฤต — ล้มเมื่อไหร่ ใช้คำตอบจากสมการแทน ผู้ใช้ได้คำตอบเสมอ

  8. ประตูหลังcanon gate

    ตัดทางเลือกให้ไม่เกิน 3 (มาตรา 11) แล้วตรวจกับ Cosmic Latte Canon — บีบจนเหลือทางเดียว หรือบังคับตัวตน = หยุดคำตอบนั้น · Belief Core บังคับใช้ผลตรวจอีกครั้ง

  9. บันทึกและตอบกลับrecord

    หนึ่งการตัดสินใจ = หนึ่งจุดในกราฟอารยธรรม (ไม่มีข้อความ/อีเมล) · นับดัชนีเสรีภาพ · สร้างรายงานที่แชร์ได้ที่ /report/<id> · หักโควตา แล้วส่งคำตอบ เส้นทาง ความเสี่ยง และลิงก์รายงานกลับหน้าเว็บ

03 · Every file

แผนที่ไฟล์ทั้งหมด

ทุกไฟล์ใน repo เป็นดาวหนึ่งดวง จัดเป็นกลุ่มตามโฟลเดอร์ เส้นคือการเชื่อมจริง: import ในโค้ด และหน้าเว็บที่โหลดไฟล์ — ข้อมูลสร้างจาก repo ด้วย scripts/build_system_map.py ทุกครั้งที่ไฟล์เปลี่ยน ไม่ได้วาดมือ
